可比样本（URL 去重后匹配金标准）：R1=15、R2=18、R3=12。**三轮跑的文章批次不同（R3 以 11-12 为主），指标差异是方向性判断，不是同卷考试。**

## 二、三轮演进结论

**R1 → R2 是质变**：输出纪律问题全部清零（模板泄漏、全英标题、脚手架、元语言），标题与金标准相似度 0.38→0.85（大量逐字一致——学会了 DeepSeek"好原标题直接透传"行为，能降重提率，但也会把 RSS 标题党一并透传），摘要均长 200→158 贴向教师分布，数字幻觉 0.27→0.11，阶段2评分差 −0.72→−0.16。**蒸馏方向正确，与 work/qa 报告的结论一致。**

**R2 → R3（testV4）守住了纪律、保真度追平 R2**：零泄漏；标题相似度 0.86、摘要相似度 0.40、数字召回 0.48 均略优于或持平 R2，数字幻觉 0.14 接近 R2 的 0.11；阶段2等级一致 9/12、评分差 +0.52（小样本）。初次快照（19 点、matched 仅 8）曾显示 groundedness 0.61 / 幻觉 0.23 疑似退化，**增量 20 点复查后确认是小样本偏差，予以撤销**。R3 相对变差的只有一处：摘要长度尾部——均长 166（R2 158、金标准 149），>200 字 6/29，且超长条多集中在未匹配金标准的 11-12 新批次（227/242/243/264 字），无法对照金标准判定是合理详实还是失控。

## 三、R3 实锤新发现：英文源 billion↔亿 换算系统性错误

同一篇 techcrunch `?p=3187315`（OpenAI 季度营收），金标准正文为 "$10 billion 首次突破、上季 $6.7 billion、年化运行率 $50 billion、Anthropic 寻求 $1.4 trillion 估值 IPO"，DeepSeek 金摘要换算全部正确（100亿/67亿/500亿/1.4万亿）。0.8B 两次运行：

- 运行A：标题《OpenAI的季度营收 **reportedly** 首次突破**10亿美元**》——量级低估 10 倍 + 英文词泄漏进中文标题；摘要"6.7亿→10亿美元、年营收运行率50亿、Anthropic 为 1.4 万亿（含云合作伙伴）"——单位全错 + 实体错绑。
- 运行B：标题正确（100亿美元），但摘要"由前一年同期的**670亿美元**跃升至**1000亿美元**、年度运行率**5000亿美元**"——量级高估 10~100 倍。

另 R3 还有 1 条全英文标题（`Is Jensen Huang's bad behavior more commonplace than it seems？`，金标准为中文《黄仁勋的不当行为是否比看起来更普遍？》——同一篇文章，模型没翻译）。R1 也有 1 条全英标题。**注意：数字级幻觉校验对这类错误不敏感（数字串 10/6.7 在正文中都存在，错的只是单位量级），0.14 的幻觉率低估了英文源真实错误率。**

增量复查补充：这两条实锤均来自初次快照（11-11/12 的 techcrunch 稿），**新增 20 点（11-12 批次）没有新的英文违规**——启发式初筛标出的另 2 条经核实为误报：《CoreWeave大涨给AI云「喘息之机」…》是金标准标题逐字透传且弯引号已按契约归一为「」（比金标准自己还守约），《Edge AI Daily 早报（11月12日）》是栏目名直取。英文源问题集中且仅集中在 techcrunch 英译中路径。

## 四、三类遗留问题（延续 work/qa 报告；第 2 条责任已判定为管线层，不在模型侧修）

1. **数值幻觉 / 单位错乱**：密集数字财经稿是重灾区。R2 期已实锤（巴西短剧 FreeReels 10 倍幻觉、医疗器械"17.65亿雷亚尔升至25.02%"单位错乱），R3 期英文源换算错误（上节）。字符级相似度看不出来，必须数字级校验。
2. **壳页直摘（责任判定：抓取层，不在模型侧修）**：wallstreetcn 壳页（"APP上线"/"清朗·违规内容整治公告"样板文）在 R1、R2 都被当新闻正经摘要；且**同一 URL 双峰**——一次正确提取全文、一次输出壳页垃圾（抓取层在壳页与全文之间摇摆）。R3 批次没遇到壳页。**判定（11-12 复盘）**：模型定位是通用新闻提取器，SKIP 契约针对「空/404/付费墙/纯导航噪音」，壳页样板文是连贯文本，忠实提取并不违约；「这是不是该 URL 应有的正文」无法从文本本身判断，属管线层职责（抓取校验/样板文特征短路/重试）。不做壳页 SKIP 训练样本——教模型跳过「公告体文本」会误杀真实的「某平台发布公告」类新闻，与通用性目标相悖。
3. **同文多次运行输出不稳定**：R2 16 组重复 URL 中摘要完全一致 **0 组**（均值相似度 0.50），**8 组数字互相矛盾**——如大摩数据中心预测同文三版："145GW 2027→2028 转移3.9GW" vs "50GW 2028→2029" vs "+1%升至+20%"，而金标准（正文实锤）是"约5吉瓦由2028推迟至2029、2028同比降4%、2029升38%"。**R3 增量后重复组从 3 组涨到 10 组（7 组含新增点），5 组数字矛盾**（部市央地、黄仁勋内部调查、AMD苏姿丰、OpenAI营收、哈工大卖气球），摘要相似度均值 0.59——问题在 11-12 批次延续，不是偶发。temperature 0.2 下采样随机性仍然很大，数字锚定弱；矛盾事实直接进生产 feed 有事实性风险。

## 五、教师侧遗留（不是模型的锅）

"120字内摘要"是纸面契约：DeepSeek 金标准自己 **214/241（89%）超标**，均值 148.8。模型摘要均长收敛到 ~158-166 是忠实模仿教师分布（与 README 的 v4 验收复盘一致）。若真要 ≤120，得先过滤/重写教师数据的超长尾部再训。

## 六、工程与数据侧提醒

- test 集合用 UUID 作点 id **不幂等**：R2 47 点只有 29 个 URL（同 URL 最多归档 4 次，且各次内容不同）。`build_dataset.py --live` 拉归档库时需按 URL+内容指纹去重，否则重复稿会以"首见样本"代表该 URL，且矛盾输出可能被当金标准学走。
- test 集合只归档最终格式化输出，**没有原始输入、没有 `_fail_reason` 标记**，无法区分「0.8B 直出」与「校验失败后云端重提」——部分与金标准逐字一致的标题可能是兜底产物而非模型能力。建议归档时补记模型来源与失败原因，否则线上重提率无法从归档库直接测算。
- R3 未匹配的 8 条 URL（多为 11-12 虎嗅/36kr）是 orig 工作流当天没归档的文章，两管线处理子集不同，属正常。

## 七、建议（按优先级）

1. **英文源定向补数据**：从 orig 的 techcrunch 金标准对提取 billion/ trillion ↔ 亿/万亿 换算样本 + 合成换算题，强化英译中数字路径；这是 R3 唯一确凿的新增退化点。
2. **管线侧加数字量级校验**：校验器比对摘要数字与正文数字的量级（≥10 倍差异即触发云端重提），能同时兜住换算错误与 10 倍幻觉——比等模型学会更快见效。
3. **壳页在管线层修，不在模型层修**：对"正文命中样板文特征"或抓取校验不过的输入直接短路/重试，不进模型；**不做壳页 SKIP 训练样本**（模型定位通用新闻提取，公告体真实新闻会被误杀）。
4. **困难样本回灌**：R2 的 8 组数字矛盾运行、R3 的 2 条英文换算实锤，天然是"小模型错→金标准对"的困难样本，按 README 飞轮机制优先补入下一版训练集。
5. **稳定性**：若生产要求同文一致，考虑 greedy（temperature 0）解码；当前 temp 0.2 下同文两次摘要相似度仅 ~0.5。
6. **归档幂等**：test 集合点 id 改用 URL hash，避免重复归档污染飞轮。
