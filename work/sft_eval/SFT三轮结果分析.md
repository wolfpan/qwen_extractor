# SFT 三轮上线结果 vs DeepSeek 金标准 对比分析（2026-11-12，testV4 110 点全量复查版）

数据源：Qdrant `10.8.0.5:6333`，**仅用 scroll API 只读拉取，未做任何写操作**。
本地 dump 与脚本：`work/sft_eval/`（dump_collections.py / analyze.py / deepdive.py / final_stats.py）。

- `ai_news_bge_orig`：DeepSeek 金标准归档（v3.107-orig），268 点 / 268 URL，11-09~11-12，含原始正文 + out_title/out_summary/out_json
- `ai_news_bge_test`（第1轮）：28 点 / 28 URL，全部 11-11
- `ai_news_bge_testV2`（第2轮）：47 点 / **29 唯一 URL**（16 个 URL 重复归档，最多同 URL 4 次），全部 11-11
- `ai_news_bge_testV4`（第3轮）：**110 点 / 94 唯一 URL**（16 组重复），11-11×2 + 11-12×108。三轮增量：初次 19 点 → 同日 39 点复查 → 晚间 **110 点全量复查（本报告口径）**，旧 dump 备份为 `_prev_testV4_19.json` / `_prev_testV4_39.json`

匹配方法：URL 归一后与 orig 对齐。**关键修正**：techcrunch 文章 ID 在 query 参数（`?p=3187315`），归一时只剥 utm 类跟踪参数、保留 `?p=`，否则会产生大量假配对（初版分析曾把不同文章错配成 sim=0.00 的"失败案例"）。匹配后用「模型摘要 bigram 在原文正文的覆盖率」做同文章校验，修正后所有 matched 对均为同文章。

可比样本（URL 去重后匹配金标准）：R1=15、R2=18、R3=24。**三轮跑的文章批次不同（R3 几乎全为 11-12），指标差异是方向性判断，不是同卷考试。** R3 未匹配 70/94（huxiu 36、tmtpost 20、wallstreetcn 12 为主）：orig 同日归档 102 点但两管线选题交集小。

## 二、三轮演进结论

**R1 → R2 是质变**：输出纪律问题全部清零（模板泄漏、全英标题、脚手架、元语言），标题与金标准相似度 0.38→0.85（大量逐字一致——学会了 DeepSeek"好原标题直接透传"行为，能降重提率，但也会把 RSS 标题党一并透传），摘要均长 200→158 贴向教师分布，数字幻觉 0.27→0.11，阶段2评分差 −0.72→−0.16。**蒸馏方向正确，与 work/qa 报告的结论一致。**

**R2 → R3（testV4，110 点口径）保真度全面追平或超过 R2**：零泄漏；标题相似度 0.91（R2 0.85）、数字召回 0.52（R2 0.48）、数字幻觉 0.07（R2 0.11）、groundedness 0.74（R2 0.71）四项均为三轮最佳；摘要相似度 0.38 与 R2 的 0.39 持平；阶段2等级一致 18/24（75%，三轮最佳）、评分差 +0.39。初次快照（19 点）的 groundedness/幻觉"疑似退化"经 39 点、110 点两轮复查确认为小样本偏差，予以撤销；"长度退化"疑虑同样撤销——均长 158.1 与 R2 的 158.4 持平、贴向金标准 150，匹配集同题配对比较学生 160 vs 教师 155，中枢已收敛。**真正的长度问题只剩尾部**：>200 字占比 16%（15/94）而金标准仅 2%（6/268）——尾部长尾不是学教师的（教师自己几乎不写超 200），是 0.8B 自身压缩不足，R2 亦然（17%）。

## 三、R3 实锤新发现：英文源 billion↔亿 换算系统性错误

同一篇 techcrunch `?p=3187315`（OpenAI 季度营收），金标准正文为 "$10 billion 首次突破、上季 $6.7 billion、年化运行率 $50 billion、Anthropic 寻求 $1.4 trillion 估值 IPO"，DeepSeek 金摘要换算全部正确（100亿/67亿/500亿/1.4万亿）。0.8B 两次运行：

- 运行A：标题《OpenAI的季度营收 **reportedly** 首次突破**10亿美元**》——量级低估 10 倍 + 英文词泄漏进中文标题；摘要"6.7亿→10亿美元、年营收运行率50亿、Anthropic 为 1.4 万亿（含云合作伙伴）"——单位全错 + 实体错绑。
- 运行B：标题正确（100亿美元），但摘要"由前一年同期的**670亿美元**跃升至**1000亿美元**、年度运行率**5000亿美元**"——量级高估 10~100 倍。

另 R3 还有 1 条全英文标题（`Is Jensen Huang's bad behavior more commonplace than it seems？`，金标准为中文《黄仁勋的不当行为是否比看起来更普遍？》——同一篇文章，模型没翻译）。R1 也有 1 条全英标题。**注意：数字级幻觉校验对这类错误不敏感（数字串 10/6.7 在正文中都存在，错的只是单位量级），0.14 的幻觉率低估了英文源真实错误率。**

增量复查补充：这两条实锤均来自初次快照（11-11/12 的 techcrunch 稿），**后续 +71 点（11-12 批次）没有新的英文违规**——110 点复查启发式命中 7 条，人工核实 5 条为误报：《CoreWeave大涨给AI云「喘息之机」…》与《从Vibe Video到Vibe World…争当「造物主」？》均为金标准标题逐字透传且弯引号已按契约归一为「」（比金标准自己还守约）；《Edge AI Daily 早报（11月12日）》是栏目名直取；《张一鸣：字节AI最早2029年或2030年追平OpenAI与Anthropic》《AI服务器+iPhone Duo双驱动，鸿海Q3净利润大增34%超预期》为含英文实体名的正常中文标题（cjk_ratio 启发式误伤）。英文源问题集中且仅集中在 techcrunch 英译中路径。

## 四、三类遗留问题（延续 work/qa 报告；第 2 条责任已判定为管线层，不在模型侧修）

1. **数值幻觉 / 单位错乱**：密集数字财经稿是重灾区。R2 期已实锤（巴西短剧 FreeReels 10 倍幻觉、医疗器械"17.65亿雷亚尔升至25.02%"单位错乱），R3 期英文源换算错误（上节）。110 点复查再添 1 条**纯捏造**实锤：techcrunch `?p=3187323`（黄仁勋不当行为）两次运行中的一次，摘要称"涉案金额约4.5亿美元，其中30%用于中国竞争对手研发""TSMC2006年专利侵权案"——4.5、30%、2006 三个数字在 7242 字原文中**一次都未出现**（原文实为 TSMC **2007**），另一次运行则正常。0.07 的最低幻觉率均值下仍藏着极端个例；字符级相似度对这类错误不敏感，必须数字级校验。
2. **壳页直摘（责任判定：抓取层，不在模型侧修）**：wallstreetcn 壳页（"APP上线"/"清朗·违规内容整治公告"样板文）在 R1、R2 都被当新闻正经摘要；且**同一 URL 双峰**——一次正确提取全文、一次输出壳页垃圾（抓取层在壳页与全文之间摇摆）。**R3 在 110 点复查中实锤**：11-12 批次遇到 2 条壳页（articles/3785777、member/articles/3785787，后者为付费会员栏目），均被直摘为"华尔街见闻APP上线"；且**两 URL 金标准库均无记录**——orig 管线同日也没归档成功，DeepSeek 大概率按契约 SKIP 了（归档库只存成功件）。即同一壳页教师会 SKIP、学生不会，三轮实测壳页全部失败（R1 1/1、R2 1/1 另重复运行中亦有、R3 2/2）。**判定（11-12 复盘，维持不变）**：模型定位是通用新闻提取器，「这是不是该 URL 应有的正文」无法从文本本身判断，属管线层职责（抓取校验/样板文特征短路/重试）。不做壳页 SKIP 训练样本——教模型跳过「公告体文本」会误杀真实的「某平台发布公告」类新闻，与通用性目标相悖。但「教师能 SKIP」说明该能力原则上可从数据学到，若未来管线层不修，可重议此判定。
3. **同文多次运行输出不稳定**：R2 16 组重复 URL 中摘要完全一致 **0 组**（均值相似度 0.50），**8 组数字互相矛盾**——如大摩数据中心预测同文三版："145GW 2027→2028 转移3.9GW" vs "50GW 2028→2029" vs "+1%升至+20%"，而金标准（正文实锤）是"约5吉瓦由2028推迟至2029、2028同比降4%、2029升38%"。**R3 110 点复查同为 16 组重复（全部 11-12 同日双跑），脚本口径 6 组数字矛盾**（部市央地、黄仁勋内部调查、AMD苏姿丰、OpenAI营收、哈工大卖气球、华东医药MASH；含"一侧摘要无数字"的组则为 8 组），摘要相似度均值 0.58（略高于 R2 的 0.50，仍低）。最刺眼个例：huxiu 4904896《为什么有些公司越亏钱越值钱》两次运行的摘要数字集合交集为零（J=0.00）——一次讲"独立调查+达摩达兰两类估值法"，一次讲"婚外情致歉+《学会估值》要点"，同文两跑产出了两条不同的"新闻"。temperature 0.2 下采样随机性仍然很大，数字锚定弱；矛盾事实直接进生产 feed 有事实性风险。

## 五、教师侧遗留（不是模型的锅）

"120字内摘要"是纸面契约：DeepSeek 金标准自己 **241/268（90%）超标**，均值 150.0。模型摘要均长收敛到 ~158 是忠实模仿教师分布（与 README 的 v4 验收复盘一致）。若真要 ≤120，得先过滤/重写教师数据的超长尾部再训。**110 点复查为"长度二选一"补上新依据**：中枢已收敛（学生均长 158 / p50 156 vs 教师 150；匹配集同题配对 160 vs 155），分歧只剩尾部——学生 >200 字 16% vs 教师 2%。尾部长尾不是从教师数据学来的，靠"过滤 >180 字金标准重训"预期收效有限；更直接的是校验器拦尾（>200~220 字触发重提）或把验收红线放宽到 ~220。数据支持二选一中的后者。

## 六、工程与数据侧提醒

- test 集合用 UUID 作点 id **不幂等**：R2 47 点只有 29 个 URL（同 URL 最多归档 4 次，且各次内容不同）；R3 亦然（110 点 / 94 URL，16 组重复）。`build_dataset.py --live` 拉归档库时需按 URL+内容指纹去重，否则重复稿会以"首见样本"代表该 URL，且矛盾输出可能被当金标准学走。
- test 集合只归档最终格式化输出，**没有原始输入、没有 `_fail_reason` 标记**，无法区分「0.8B 直出」与「校验失败后云端重提」——部分与金标准逐字一致的标题可能是兜底产物而非模型能力。建议归档时补记模型来源与失败原因，否则线上重提率无法从归档库直接测算。
- R3 未匹配的 70/94（多为 11-12 虎嗅/钛媒体/华尔街见闻）是 orig 工作流当天没归档的文章，两管线处理子集不同，属正常——但也意味着 R3 指标基于 24 条匹配对，未匹配 70 条的质量无金标准参照。

## 七、建议（按优先级）

1. **英文源定向补数据**：从 orig 的 techcrunch 金标准对提取 billion/ trillion ↔ 亿/万亿 换算样本 + 合成换算题，强化英译中数字路径；这是 R3 唯一确凿的新增退化点（110 点复查无新增案例，但 2 条旧实锤仍在库，且 §四.1 又添同路径的捏造数字案例）。
2. **管线侧加数字量级校验**：校验器比对摘要数字与正文数字的量级（≥10 倍差异即触发云端重提），能同时兜住换算错误与 10 倍幻觉——比等模型学会更快见效。
3. **壳页在管线层修，不在模型层修**：对"正文命中样板文特征"或抓取校验不过的输入直接短路/重试，不进模型；**不做壳页 SKIP 训练样本**（模型定位通用新闻提取，公告体真实新闻会被误杀）。
4. **困难样本回灌**：R2 的 8 组数字矛盾运行、R3 的 2 条英文换算实锤 + techcrunch 3187323 捏造数字运行 + 11-12 批次 6 组数字矛盾运行，天然是"小模型错→金标准对"的困难样本，按 README 飞轮机制优先补入下一版训练集。
5. **稳定性**：若生产要求同文一致，考虑 greedy（temperature 0）解码；当前 temp 0.2 下同文两次摘要相似度 R2 ~0.50 / R3 ~0.58，数字矛盾组占比 6~8/16。
6. **归档幂等**：test 集合点 id 改用 URL hash，避免重复归档污染飞轮。
