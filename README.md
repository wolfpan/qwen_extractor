# qwen_extractor

把 **Qwen3.5-0.8B** 微调成一个「科技新闻标题/摘要提取器」，替换 n8n 抓新闻管线里的 DeepSeek——最主要的动因是**省钱**。

## 这个项目在干嘛

我有一条 n8n 管线，平均每天处理 150 条科技新闻，其中「读正文 → 写标题 + 摘要」这一步原来交给 DeepSeek：缓存命中率只有 50%~60%，开销以输出 token 为主，一天 1.5 元左右，一年下来 400 多元——而且这还都是按 DeepSeek 闲时折扣价跑的。于是我决定换成本地部署。

但负责跑模型的笔记本已经将近 10 年了：R5-2500U + 32GB DDR4-2400 内存，跑 3B 以上的模型无望。所以干脆训练一个**专门用于新闻提取和摘要的 0.8B 模型**，做 4bit 量化（Q4_K_M，约 517MB），部署在 Ollama 上——纯 CPU 实测 26~30 token/s，完全满足管线长期在后台提取的性能要求。

这个项目教会这个小模型只干这一件事：

- **输入**：清洗过的新闻正文（可能带原标题）
- **输出**：只有 2 个键的 JSON——

```json
{"新闻标题":"15-30字核心事件标题","核心摘要":"120字内单段摘要，保留精确数字、单位、日期"}
```

- 正文是垃圾（空 / 404 / 付费墙 / 纯导航噪音）时，输出 `{"新闻标题":"SKIP","核心摘要":"SKIP"}`，让管线跳过。

小模型干粗活，干砸了管线的校验器会兜底转云端大模型重提。SFT 的目标就是把「事后兜底」内化成模型本能，降低重提率。

设计原则：做**通用的新闻提取器**——只内化任务契约（输出格式、长度、SKIP 边界），不做任何站点级特化补丁；输入质量问题（抓到壳页、抓取失败）归管线层负责，不归模型。

效果一句话：三轮 SFT 迭代的线上对照评测（同一篇新闻，0.8B 输出 vs DeepSeek 金标准）——标题对齐度 0.38 → 0.86、教师摘要数字召回 0.21 → 0.48、输出纪律违规全部清零；遗留模型侧两个短板——英文源数字换算、同文输出不稳定（壳页直摘经分析判定为抓取层问题，不在模型侧修）。详见[效果怎么样](#效果怎么样)。

## 训练数据从哪来（这是本项目的核心）

**不是网上爬的，也不是手写的。** 生产管线每天跑，会自动把「原始正文 + DeepSeek 输出」归档进 Qdrant（`ai_news_bge_orig` 集合，append-only 滚动积累）。从归档库取真实配对当金标准，再合成少量 SKIP 样本：

| 版本 | 文件 | 条数 | 说明 |
|---|---|---|---|
| v3 | `data/dataset*.json` | 112 = 99 train / 13 val | 首版：100 条金标准 + 12 条合成 SKIP，训练出 v3 模型 |
| v4 | `data/dataset_v4*.json` | 167 = 150 train / 17 val | `--live` 在线全量拉归档库构建（飞轮已转一圈） |

格式是 Alpaca 三键 `{instruction, input, output}`。`instruction` 和 `input` 是从 n8n 生产节点里**逐字提取**的提示词，不是重新写的。

两个关键保真操作（细节见 `SFT方向分析.md`）：

1. **训练输入 == 推理输入**：归档正文只经过旧版清洗，而线上 0.8B 看到的是新版（v4.9）清洗后的文本。`work/build_dataset.py` 把生产工作流的清洗正则逐条移植了过来，保证模型「学的」和「用的」是同一个分布。
2. **输出契约归一**：金标准里的弯引号 `“”` 统一替换成提示词声明的 `「」`，教模型遵守自己声明的契约。

## 训练配方一句话

Colab T4 + Unsloth + LoRA（r=16 全线性层，fp16 不量化——保护数字敏感度），`max_seq_length=4096` 与 Ollama `num_ctx` 对齐，**loss 只算在回答上**（不让模型学着复述正文），3 epochs ≈ 39 步，`eval_loss` 择优加载防过拟合，导出 Q4_K_M GGUF（约 517MB）。

## 效果怎么样

### 离线验收（验证集）

- **v3**：离线验收（13 条验证集 + 四项标准）**8 条 PASS**。3 条 FAIL 全是「输出纪律」问题（多吐了一个键 / JSON 结束后没停住）——v4 的主攻方向。
- **v4**：离线验收（17 条验证集）**15/17 PASS**。v3 的三类失败（SKIP 空输出、Extra data、JSON 骨架损坏）全部消失——复盘确认那是 repeat_penalty=1.2 惩罚 ChatML 骨架 token 造成的解码假象，模型本身没有此问题；剩余 2 条 FAIL 均为摘要超长（201 字 / 254 字），根源是金标准教师数据自带超长尾部，模型忠实学到了分布，属数据侧遗留。

### 线上实测（生产归档对照评测，2026-11-12）

离线验收只能证明「学会了」，真实效果看生产。评测方式：**双管线并行**——orig 管线（DeepSeek 提取，阶段1）与 test 管线（0.8B 提取，随迭代换模型）跑同一批新闻源，各自把最终输出归档进 Qdrant；评测按 URL 把两边归档对齐成「同一篇文章的两个答案」，以 DeepSeek 侧为金标准。全程只读（scroll API），脚本与全量 dump 在 `work/sft_eval/`，指标可复算。

三轮 SFT 迭代对应三个归档集合：`ai_news_bge_test`（第1轮）→ `ai_news_bge_testV2`（第2轮）→ `ai_news_bge_testV4`（第3轮，即当前发布的 v4 模型）。URL 去重后：金标准库 241 条（11-09~11-12），三轮各 28/29/29 个唯一 URL，其中 **15/18/12 条能与金标准同卷对比**。

**四个口径须知**（先说清，免得误读）：

1. **三轮不是同一批考卷**：各轮文章批次不同、可比样本 12~18 条，对比是方向性判断。第3轮初查（n=8）曾显示保真度退化，样本翻倍后确认是小样本偏差，已撤销——小样本在线评测，结论要等样本。
2. **归档的是管线最终输出**：不区分「0.8B 直出」与「校验失败后云端重提」，所以指标是 0.8B 能力的上界（从第1轮归档保留着大量赤裸失败看，多数点位应为直出）。
3. **打分不是 0.8B 做的**：归档里的重要性等级/评分/六维打分出自阶段2打分模型（qwen3.7-flash），两条管线共用。它只作下游影响的旁证，不计入 0.8B 的提取能力。
4. **教师自己也不守纸面契约**：声明「摘要 120 字内」，金标准 241 条里 89% 超标（均值 149 字）。所以长度以教师**真实分布**为基准，不以 120 字为基准。

核心指标（vs 金标准；相似度为字符级 SequenceMatcher ratio）：

| 指标 | 第1轮 | 第2轮 | 第3轮 (v4) |
|---|---|---|---|
| 标题相似度 | 0.38 | 0.85 | **0.86** |
| 摘要相似度 | 0.15 | 0.39 | **0.40** |
| 教师摘要数字召回（教师摘要中的数字被保留的比例） | 0.21 | 0.48 | **0.48** |
| 数字幻觉率（摘要数字不见于正文） | 0.27 | 0.11 | **0.14** |
| 摘要-原文覆盖率（摘要 bigram 在原文正文中的覆盖率） | 0.54 | **0.71** | 0.67 |
| 摘要均长（教师 149 字） | 200 | 158 | 166 |
| 纪律违规（模板泄漏/英文标题/脚手架/元语言） | 1/1/3/3 | **全零** | 0/2/0/0 |

**第1轮 → 第2轮是质变。** 第1轮六大失败模式齐活，最恶性的是提示词模板泄漏——标题吐出 67 字：`八年平头哥闯关港股，阿里分拆背后的算力资本局 15-30字核心事件标题（英文译为中文）：…`，把 instruction 原文和 JSON 骨架当场复述；另有全英标题、「背景：/趋势：」脚手架、「本文作者为…」元语言。第2轮纪律违规**全部清零**，标题相似度 0.38→0.85——大量标题与教师**逐字一致**：模型学会了教师「好原标题直接透传」的行为（能降重提率，但也会把 RSS 标题党原样带进来），还学会了教师没做到的弯引号→「」契约归一。

**第3轮追平第2轮。** 标题相似度 0.86、数字召回 0.48、幻觉率 0.14，零泄漏零脚手架；新增 20 条批次无新违规。唯一变差的是长度尾部：摘要均长 166（第2轮 158），>200 字 6/29。

**三类遗留问题（均有实锤案例；第 3 条经分析判定责任在管线层）：**

1. **英译中数字量级换算错误（最严重）。** 同一篇 TechCrunch（正文：OpenAI 季度营收首破 $10 billion，上季 $6.7 billion，年化运行率 $50 billion；教师换算全对：100亿/67亿/500亿），v4 两次运行：一次标题 `OpenAI的季度营收 reportedly 首次突破10亿美元`——低估 10 倍还泄漏英文词；一次标题对了、摘要却写成「670亿美元跃升至1000亿美元、运行率5000亿美元」——高估 10~100 倍。同轮还有 1 条全英标题没翻译。**英文源是贯穿三轮的持续弱点**，且量级换算错对「数字串比对」类校验天然免疫（"10亿"的 10 在正文里存在，错的是单位）——比幻觉更危险。
2. **同文多次运行输出不稳定。** 归档不幂等（UUID 点 id）意外提供了稳定性样本：第2轮 16 组同文重复，摘要完全一致 **0 组**，**8 组数字互相矛盾**；第3轮 10 组重复，5 组矛盾。矛盾是事实级的——大摩数据中心预测（正文实锤「约 5GW 由 2028 推迟至 2029，2028 年美国新增容量同比降约 4%、2029 年升约 38%」），同一 URL 归档 4 次，其中三次给出三个矛盾版本：「145GW 2027→2028 转移3.9GW」/「50GW，2028 增长 9%、2029 增长 20%」/「增速由 +1% 升至 +20%」——第四次甚至把当次抓回来的壳页样板文摘要成了新闻（见下条，一个 URL 实锤两类问题）。temperature 0.2 下仍有这种方差，数字锚定弱；需要一致性的场景应考虑 greedy 解码。
3. **壳页直摘——判定为抓取层问题，不在模型侧修。** 抓取层偶尔拿回的不是正文而是站点壳页（「APP 上线公告 / 违规内容整治公告」类样板文），模型把样板文当正文摘要（第1、2轮各实锤 1 次），且同一 URL 双峰——一次正确提取全文、一次抓回壳页。严格说**模型没有违约**：SKIP 契约针对「空 / 404 / 付费墙 / 纯导航噪音」，而壳页样板文是连贯文本，对通用提取器而言忠实提取才是正确行为；「这是不是该 URL 应有的正文」从文本本身判断不了，只有管线层能判断。反过来，把壳页做成 SKIP 训练样本会教模型跳过「公告体文本」——而真实科技新闻完全可能就是「某平台发布公告」，会造成误杀，与通用新闻提取器的定位相悖。修法在管线：抓取校验 / 样板文特征短路 / 失败重试，别让壳页进模型。

**下游影响（再次强调：打分是阶段2模型做的，不是 0.8B）：** 同一打分器给两条管线的阶段1输出打分，分差只反映提取质量差距——等级一致率 8/15 → 10/18 → 9/12，评分差（test−orig）−0.72 → −0.16 → +0.52，收敛到与 DeepSeek 管线基本一致。这是「阶段1接近教师」的独立旁证。

**方法论踩坑（给同样想做在线评测的人）：**

- URL 匹配小心 query 参数：TechCrunch 文章 ID 在 `?p=` 里，归一化时把 query 一律剥掉会把不同文章错配成对，凭空造出一批「相似度 0.00 的恶性失败」。匹配后还要做同文章校验（摘要 bigram 在正文的覆盖率）兜底。
- 字符级相似度看不见数字错误，数字级校验看不见量级错误。三层都要：字符串相似度（对齐度）→ 数字集合比对正文（幻觉）→ 抽样人工核单位量级（换算错）。
- 别拿纸面契约考核学生，先看教师守不守约（教师 89% 超「120字」，学生收敛到 ~150-166 是忠实蒸馏而非失控）。
- 归档要幂等 + 记录来源：UUID 点 id 导致重复归档污染数据集构建；不记「直出/兜底」评测只能给上界；顺手记 `_fail_reason` 还能白得困难样本飞轮。

## 部署（Ollama + n8n）

模型下载：[Phanai/qwen_extractor](https://huggingface.co/Phanai/qwen_extractor)（`qwen3.5_0.8b_news_extractor_v4.gguf`，Q4_K_M，约 517MB；上一版 v3 仍可下载）：

```bash
# 方式一：直接下载
curl -LO https://huggingface.co/Phanai/qwen_extractor/resolve/main/qwen3.5_0.8b_news_extractor_v4.gguf
# 方式二：Ollama 直接拉（拉完仍需下方 Modelfile 重套模板，模型没内嵌模板）
ollama pull hf.co/Phanai/qwen_extractor
```

⚠️ **必须手写 Modelfile**。Unsloth 导出时不会给这个模型内嵌对话模板，Ollama 默认模板对不上会导致输出崩坏。TEMPLATE 必须与训练时的 ChatML 逐字一致：

```
FROM ./qwen3.5_0.8b_news_extractor_v4.gguf
TEMPLATE """<|im_start|>system
{{ .System }}<|im_end|>
<|im_start|>user
{{ .Prompt }}<|im_end|>
<|im_start|>assistant
"""
PARAMETER temperature 0.2
PARAMETER num_ctx 4096
PARAMETER num_predict 500
PARAMETER repeat_penalty 1.05
```

⚠️ **repeat_penalty 用 1.0–1.05，别沿用 v3 时代的 1.2**：1.2 会惩罚 ChatML 骨架 token，在 llama.cpp / Ollama 上可能诱发 JSON 骨架损坏或 SKIP 误判（`format:json` 只挡得住 Extra data）——这是 v4 验收复盘的结论。

```bash
ollama create qwen_extractor_v4 -f Modelfile
```

n8n 阶段1节点只换 model 名，`think:false`、`format:json` 保持不变。

## 怎么继续迭代（数据飞轮）

1. 生产管线每跑一轮，归档库自动积累新的「正文 ↔ 金标准」配对
2. 每周跑 `python work/build_dataset.py --live` 在线全量拉归档库 → 数据集自动变大（v3 → v4 已经从 112 涨到 167）
3. 线上触发云端重提的失败案例（`_fail_reason`），其重提结果天然是「小模型错 → 金标准对」的困难样本，优先补入下一版
4. 同文重复运行里的**数字矛盾对**（一版对一版错，见线上实测）同样是天然困难样本；线上评测实锤的英文源换算错案例按轮次回灌（壳页案例不回灌——那是抓取层问题，见设计原则）
5. 下一轮数据侧主攻：从金标准库的 techcrunch 配对提取 billion/trillion↔亿/万亿 换算样本；教师摘要的超长尾部先清洗再当金标准（要真执行 120 字契约，得先让教师守约）。**不做壳页 SKIP 样本**——模型定位是通用新闻提取器，壳页识别归管线层（见第 6 条）
6. 管线侧两处加固：①校验器加**数字量级规则**——摘要数字与正文数字相差 ≥10 倍即触发云端重提，对英文源换算错和 10 倍幻觉比等模型学会更快兜底；②抓取层加**壳页短路**——正文命中样板文特征或与 URL 内容校验不过时重试/跳过，不进模型

## 已知局限

- v3 金标准只有 100 条（v4 已滚动到 167，评测时点金标准库 241 条），长尾版式（如 36kr 快讯样本极少）泛化有限，靠飞轮慢慢补
- SKIP 样本全部是合成的，只覆盖契约内形态（空页/404/付费墙/导航噪音），真实触发率待更多生产样本检验；壳页直摘已判定为抓取层问题，不计入模型局限（见线上实测一节的设计原则）
- **英文源（techcrunch）英译中是持续弱点**：全英标题、英文词夹杂、billion↔亿 量级换算错误在三轮中反复出现，且量级错对自动校验免疫
- **输出不稳定**：temperature 0.2 下同文两次运行的摘要相似度仅 ~0.5-0.6，约半数重复组数字互相矛盾——对事实性敏感的消费方应加数字校验或改用 greedy 解码
- 归档窗口初期只有 3 天，题材有时效同质（比如黄仁勋事件占了 15 条），滚动再采集自然缓解
- test 侧归档不幂等（UUID 点 id，同 URL 最多重复归档 4 次）且不记模型来源/失败原因：`--live` 构建需按 URL 去重，评测只能给出能力上界
